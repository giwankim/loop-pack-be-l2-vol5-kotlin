# 주문 생성 시 단가를 확정에도 사용한다

주문 생성과 확정 사이에 상품 가격이 바뀔 수 있다. 서버가 주문 생성 시 상품 가격을 주문 품목의 단가로 기록하고, 확정할 때도 저장된 단가와 수량으로 정해진 주문 금액을 사용한다. 확정 시 현재 상품 가격과 다르다는 이유로 거절하거나 현재 가격으로 다시 계산하지 않는다.

## 비교한 대안과 선택

- 생성 당시 가격을 보존하면 DRAFT에 기록된 금액과 확정 결제액이 이어진다. 대신 상품 가격이 오른 뒤에도 이전 가격으로 결제될 수 있다.
- 확정 시 현재 상품 가격과 비교해 다르면 검증 실패로 거절할 수도 있다. 이 경우 변경된 가격을 안내하고 주문을 다시 만드는 흐름이 필요하다.

설계 인터뷰 Q2에서 사용자는 두 번째 대안도 가능하다고 짚은 뒤, 이번 구현에서는 생성 시 가격을 사용하는 첫 번째 대안을 선택하고 명시적으로 문서화하도록 했다.

## 결과와 경계

- 10,000원에 생성한 주문은 현재 상품 가격이 12,000원으로 올라도 10,000원으로 확정한다. 가격이 8,000원으로 내려도 저장된 10,000원을 사용한다.
- 확정 전 상품의 존재·삭제 여부, 수량, 재고와 포인트 잔액 검사는 그대로 필요하다. 가격 보존이 판매 가능 여부나 재고·포인트 확보를 보장하지 않는다.
- 이번 범위에는 주문 만료가 없다. 오래된 DRAFT도 나머지 확정 조건을 충족하면 생성 당시 단가를 사용한다.
- 나중에 이 정책을 바꾼다면 이미 생성된 DRAFT에 새 정책을 적용할지 따로 결정해야 한다. 확정된 주문의 결제 기록을 현재 가격으로 재계산하지 않는다.
- 상품 이름·브랜드 등 금액 외에 어떤 정보를 주문에 보관할지는 후속 인터뷰에서 정한다.
